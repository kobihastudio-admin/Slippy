# กติกาจัดเก็บรูปภาพและแบรนด์

สถานะ: active — กติกาการจัดเก็บใน repository
วันที่จัดทำ: 2026-09-09
ผู้รับผิดชอบ: รอมอบหมายโดยผู้ดูแลโปรเจกต์

## ต้นฉบับและไฟล์ส่งออก

ใช้ [ทะเบียน](asset-register.csv) ระบุต้นฉบับของแต่ละภาพ เก็บไฟล์ส่งออกไว้ข้างแอปตาม path ที่ใช้งาน กรณี SVG ที่สคริปต์อ้างอิง ใช้ web/scripts/generate-icons.mjs เป็นหลักฐานความสัมพันธ์ ห้ามแก้ไฟล์ส่งออกแทน master โดยไม่บันทึกเหตุผล ไม่รันตัวสร้างไอคอนเพียงเพื่ออัปเดตทะเบียน เพราะอาจเขียนทับภาพปัจจุบัน

ต้นฉบับภายนอกให้บันทึก URL หรือ asset ID ที่เข้าถึงได้พร้อมผู้รับผิดชอบ ห้ามสมมติว่า PNG คือ master หรือภาพที่พบใน repository มีสิทธิ์เผยแพร่แล้ว

## การตั้งชื่อไฟล์ใหม่

ใช้ `slippy-<subject>-<variant>-<width>x<height>.<ext>` สำหรับภาพส่งออก เช่น `slippy-assistant-light-1024x1024.png`; ต้นฉบับ vector ใช้ `slippy-<subject>-master.svg` เมื่อได้รับการยืนยันว่าเป็น master แล้ว ภาพตามเหตุการณ์ใช้วันที่ `YYYY-MM-DD` เมื่อจำเป็น ใช้ตัวพิมพ์เล็กและขีดกลาง หลีกเลี่ยง final, final2, latest

ข้อยกเว้น: ชื่อที่ framework, Xcode asset catalog, Android resource หรือ external URL กำหนด ให้ใช้ convention ของแพลตฟอร์ม เช่น icon.svg และ AppIcon-1024.png ชื่อไฟล์เก่าคงไว้จนตรวจ references และทดสอบแอปที่ได้รับผลครบ

## ข้อมูลและสถานะ

ทุกไฟล์ต้องมี path, หมวด, hash, ขนาด, source_path/source_evidence, owner, rights, status และวันที่ทบทวนในทะเบียน ค่าที่ไม่ทราบใช้ unknown หรือ unassigned; เมื่อยืนยันสิทธิ์ให้ใส่ชนิดสิทธิ์และลิงก์หลักฐาน ไม่คัดลอก MIT จาก README มาใช้กับภาพโดยอัตโนมัติ

สถานะ: `inventoried-needs-review` = พบไฟล์; `rights-attested-needs-source-review` = มีคำยืนยันสิทธิ์จากผู้ใช้ แต่ยังต้องตรวจต้นทางรายไฟล์; `approved` = ผู้รับผิดชอบอนุมัติแหล่งที่มา สิทธิ์ และการใช้งานพร้อมหลักฐานแล้ว; `archived` = เลิกใช้พร้อมเหตุผลและภาพทดแทน ต้องบันทึกผู้อนุมัติและหลักฐานใน source_evidence หรือบันทึกประกอบก่อนเปลี่ยนเป็น approved

## ขั้นตอนบำรุงรักษา

1. ตรวจไฟล์ใหม่และแหล่งที่มา แล้วเพิ่มแถวในทะเบียนพร้อมการเปลี่ยนไฟล์
2. อ่านขนาดจากไฟล์จริงและคำนวณ SHA-256 ใหม่เมื่อเนื้อหาเปลี่ยน
3. ตรวจ source_path และ references ในแอปก่อนย้าย/เปลี่ยนชื่อ/ลบ
4. ให้ผู้ดูแลตรวจภาพและสิทธิ์ก่อนเปลี่ยนสถานะเป็น approved
5. เก็บประวัติด้วย Git; ไม่มีการลบตามอายุอัตโนมัติจนองค์กรกำหนดนโยบายเก็บรักษา

ไม่เก็บใบเสร็จหรือภาพส่วนบุคคลของผู้ใช้งานจริงใน public assets หรือทะเบียนนี้
