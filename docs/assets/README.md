## ขอบเขตและวิธีอ่าน

ทะเบียนครอบคลุมไฟล์ภาพที่ rg --files มองเห็นใน repository ตาม .gitignore ณ วันที่สำรวจ ไม่รวม dependency, build, worktree, รูปใน Storage/Drive/NAS หรือกราฟิกที่วาดด้วยโค้ด ทุกแถวมี path, หมวด, ขนาดไฟล์, ความกว้าง/สูงเมื่ออ่านได้, SHA-256, สถานะ, ต้นฉบับ/หลักฐาน, เจ้าของ และสิทธิ์

ขนาด PNG อ่านจาก header เป็นพิกเซล; ขนาด SVG อ่านจาก viewBox เป็นหน่วยพิกัด ไม่ใช่ความละเอียดพิกเซลของภาพส่งออก

คำยืนยันเรื่องสิทธิ์: ผู้ใช้ยืนยันเมื่อ 2026-09-13 ว่า “KOBIHA Studio เป็นเจ้าของหรือได้รับสิทธิ์ใช้ภาพทั้งหมดในทะเบียน” จึงบันทึก owner และ rights ตามคำยืนยันนี้ครบ 136 แถว สถานะ `rights-attested-needs-source-review` แยกคำยืนยันเรื่องสิทธิ์ออกจากการตรวจต้นทางรายไฟล์ โดย `source_path` ที่กรอกมาจากการอ่านสคริปต์สร้างภาพ ไม่ใช่หลักฐานว่าไฟล์ปัจจุบันสร้างจากสคริปต์เวอร์ชันนี้จริง คำยืนยันนี้เป็นข้อมูลที่ผู้ใช้ให้ ไม่ใช่เอกสารทางกฎหมายที่แนบใน repository SHA-256 ใช้ตรวจไฟล์เหมือนกันทุกไบต์ ไม่ตัดสินว่าลบได้

## ตำแหน่งภาพ

| หมวด | ตำแหน่ง | หมายเหตุ |
|---|---|---|
| ต้นฉบับ SVG สำหรับตัวสร้างไอคอน | web/public/app-icon-1024.svg, line-oa-icon.svg, og-image.svg, social/ | อ้างอิงใน web/scripts/generate-icons.mjs |
| ไอคอนส่งออก | web/public/icons/ และ PNG บางไฟล์ใน web/public/ | มีสำเนาที่ root สำหรับ URL ที่แอปใช้ |
| ภาพออกแบบและผู้ช่วย | web/public/design/, web/public/images/ | ต้นฉบับภายนอกและสิทธิ์รอตรวจสอบ |
| LINE mockup | api/src/assets/ | มีหลายเวอร์ชัน ห้ามเลือกฉบับอนุมัติจากชื่อไฟล์อย่างเดียว |
| iOS / Watch | ios/**/Assets.xcassets/ | รักษาชื่อและ Contents.json |
| Expo และ native bundle | mobile/assets/, mobile/ios/ | รักษา path ที่ config อ้างอิง |
| ไอคอนเส้นทางเว็บ | web/src/app/*.svg | ใช้ convention ของ framework |

กราฟิกที่สร้างในโค้ด: web/src/components/ui/logo.tsx, icons.tsx, ios/Slippy/Views/Shared/SlippyLogoMark.swift และ BrandIcons.swift อยู่ในขอบเขตการตรวจแบรนด์ แต่ไม่ใช่แถวไฟล์ภาพใน CSV

## งานตรวจสอบต่อ

- มอบหมายผู้รับผิดชอบภาพและแบรนด์
- ตรวจแหล่งที่มาและผู้สร้างของแต่ละภาพ พร้อมบันทึกลิงก์หลักฐาน; มีคำยืนยันสิทธิ์ครอบคลุมภาพทั้งหมดจากผู้ใช้เมื่อ 2026-09-13
- ระบุ master ที่อนุมัติและตรวจความสอดคล้องข้ามแพลตฟอร์ม
- ตรวจไฟล์ hash ซ้ำกับจุดใช้งานก่อนรวมไฟล์ ภาพเหมือนกันอาจจำเป็นต้องอยู่หลาย bundle
- อัปเดตทะเบียนเมื่อเพิ่ม เปลี่ยน ย้าย หรือเลิกใช้ภาพ โดยคงข้อมูลเจ้าของและสิทธิ์ที่ตรวจแล้ว
