# กติกาดูแลเอกสาร

สถานะ: active — กติกาการจัดเก็บที่เริ่มใช้ใน repository นี้
วันที่จัดทำ: 2026-09-09
ผู้รับผิดชอบ: รอมอบหมายโดยผู้ดูแลโปรเจกต์

## จุดเริ่มต้นและขอบเขต

ใช้ [สารบัญกลาง](README.md) ค้นหาเอกสาร และ [โครงสร้างจริง](MONOREPO_STRUCTURE.md) ค้นหาโค้ด เมื่อย้ายเอกสารต้องปรับสารบัญและตรวจลิงก์ที่อ้างอิงให้ครบ กติกานี้ครอบคลุมเอกสารของโปรเจกต์ใน repository ไม่ครอบคลุมเอกสารผู้ใช้ในระบบจริง, Drive หรือ NAS และไม่ใช่การรับรอง ISO

## สถานะเอกสาร

- `draft`: ร่างหรือโครงที่ยังต้องเติมเนื้อหา
- `needs-review`: มีเนื้อหาแล้ว แต่ยังไม่ได้ยืนยันความถูกต้องกับระบบปัจจุบัน
- `active`: ผ่านการตรวจในขอบเขตที่ระบุและใช้เป็นเอกสารอ้างอิง
- `archived`: เลิกใช้แล้ว ต้องระบุเหตุผล วันที่ และเอกสารทดแทน

สถานะในสารบัญเป็นทะเบียนหลัก สถานะเอกสารไม่ใช่หลักฐานว่าฟีเจอร์พัฒนาเสร็จหรือ deploy แล้ว เอกสารเดิมถูกจัดเป็น needs-review หรือ draft ตามเนื้อหาที่พบ ไม่อนุมานว่าแผนเก่าถูกยกเลิกเพียงเพราะวันที่เก่า

## การเพิ่มและแก้ไข

1. เลือกหมวดในสารบัญ เอกสารเทคนิคทั่วไปอยู่ใน docs/; runbook อยู่ docs/operations/; เอกสารออกแบบผลิตภัณฑ์อยู่ docs/design/; แผนและแบบออกแบบอยู่ docs/superpowers/plans/ และ specs/; คู่มือเฉพาะแอปอยู่ข้างแอปได้
2. ไฟล์ใหม่ใช้ lowercase-kebab-case.md; เอกสารตามเหตุการณ์ใช้ YYYY-MM-DD-topic.md ใช้วันที่จริง ไม่เปลี่ยนชื่อไฟล์เก่าโดยไม่ตรวจลิงก์
3. ระบุชื่อ วัตถุประสงค์ ขอบเขต สถานะ ผู้รับผิดชอบ วันที่ทบทวน และลิงก์เกี่ยวข้องไว้ต้นเอกสาร หากยังไม่ทราบผู้รับผิดชอบให้ระบุรอมอบหมาย
4. เพิ่มหรือแก้แถวในสารบัญพร้อมการเปลี่ยนเนื้อหา ใช้ Git เก็บประวัติ ไม่สร้าง final-final หรือสำเนา v2 ของเอกสารอ้างอิงเดียวกัน
5. ผู้ดูแลส่วนที่เกี่ยวข้องตรวจเนื้อหาก่อนเปลี่ยนเป็น active และทบทวนเมื่อโค้ด/ข้อกำหนดที่อ้างถึงเปลี่ยน
6. เมื่อเลิกใช้ ให้เปลี่ยนเป็น archived พร้อมเหตุผล วันที่ และลิงก์ฉบับทดแทน คงไฟล์และลิงก์เดิมจนตรวจผู้ใช้งานครบ ไม่ลบอัตโนมัติ

## งานค้างที่ต้องอาศัยเจ้าของข้อมูล

มอบหมายเจ้าของเอกสารรายหมวด ตรวจความถูกต้องของเอกสารเดิม และกำหนดอายุเก็บรักษาตามประเภทข้อมูลร่วมกับผู้รับผิดชอบองค์กร ปัจจุบันยังไม่มีตารางอายุเก็บรักษาที่รับรองแล้ว
